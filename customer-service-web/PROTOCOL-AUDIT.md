## 已实现的变化

- 新增 `desk/pdd_protocol.py`，统一构建号发现、HTTP 返回码、鉴权帧、心跳和序号同步。
- 移除旧固定构建号。工作台 HTML 中发现当前脚本版本，内存缓存一小时；无法发现则明确报错，不猜测版本。
- 连接只有在鉴权通过后才显示已连接；鉴权超过 12 秒失败，拒绝状态、前后矛盾的鉴权和二进制帧均明确报告。
- JSON 通道每 25 秒发送应用层心跳，等待对应回包最多 12 秒。心跳、接收或同步失败会结束本轮并重连。
- 接入 `seq_type=1` 的聊天消息同步，首次从当前序号建立基线；每 15 秒查询增量并持久化游标。
- 恢复消息先入库，再推进游标。数据库失败不前移游标；分页不推进、有缺口、序号回退和页数超限都会停止并报告。
- 恢复消息统一进入人工处理，不对旧咨询自动发送回复；平台 msg_id 去重在修改会话信息之前完成，避免重复数据覆盖新会话商品信息。
- 同一店铺切换客服账号时清空旧账号同步游标与协议检查结果。
- 当前推送解析兼容数字/字符串类型字段，保留平台 conv_id 和真实 chat_type。发送时仅传递已观察到的 chat_type，不编造签名或风控参数。
- 发送补齐普通时间戳和已读状态字段，但当前 `anti_content`、`hash`、`random` 等来源尚未接入。真实发送接受情况仍需指定测试会话验证。
- 工作台新增“检查协议”，只验证构建号、鉴权、心跳及同步初始化，结果不包含 Cookie/token，不发送买家消息。运行中请先断开连接再做独立检查。

## 明确的边界

本次是“已实测可用的旧 JSON 通道 + 当前 HTTP 消息序号同步”，不是 Titan 二进制实现。平台当前客户端仍有新旧两套链路；只有在现有链路真实不可用或有明确需求时才应迁移 transport。

本次尚未观察到真实买家消息，也没有实发测试。页面显示“鉴权/心跳/同步正常”不等于“所有卡片与回复发送已验证”。若平台要求额外验证或风控参数，系统会显示错误，不静默绕过或猜造字段。

用户本轮选择暂不提供专用测试会话，因此保留现有接收连接，不进行真实买家消息发送测试。发送侧状态继续显示未验证。正式网页已确认“已连接”和“消息序号同步正常”，界面证据为 `evidence/protocol-2026-10-28/workstation-protocol-result.png`。

## 历史功能上线验证

新增历史会话/历史消息 API 及网页入口。真实店铺的历史会话可从 20 条继续加载到 40 条；一条会话在网页读取出 9 条完整消息，另一条长会话先载入 50 条、再补到 63 条且已到最早消息。两种分页均在真实平台响应上验证。历史浏览不调用 AI、不发送消息；显式接管才导入最新页并进入人工接待。

自动测试共 43 项通过，覆盖只读查询、平台大消息 ID、消息方向与时间、消息 ID 分页、权限、显式导入去重及本地消息时间排序。原始历史正文和买家标识不写入源码或本记录。


## 买家昵称解析验证

当前 `latest_conversations` 消息携带 `user_info.nickname`，不能只读 `from.nickname` 或消息顶层 `nickname`。客服发送最后一条消息时，也应从绑定买家 UID 的 `user_info` 获取昵称，不能把客服昵称赋给买家。

当前加载资源中确认补查接口为 `/latitude/user/userInfoWithTags`，POST 请求参数 `uid`，可带 `chatType`；真实响应 `result` 含与请求相同的 `uid` 和 `nickname`。实现只保存昵称，按店铺、UID、聊天类型缓存，限制同时补查数为 4，失败短暂缓存并保留已知昵称。真实样本的 20 个历史会话和 5 个本地会话均获取成功，平台脱敏星号按原样显示。昵称获取及历史验证均未发送买家消息。


## 结构化消息与媒体展示验证

真实图片消息 `type=1` 的地址位于 `content`，`info` 提供宽高；真实商品咨询 `type=0,sub_type=0` 的 `info` 提供 `goodsID`、`goodsName`、`goodsThumbUrl`、`goodsPrice`、`couponPromoPrice`、`linkUrl`。该商品卡的 `goodsPrice` 和 `couponPromoPrice` 为元，不能再次除以 100。仅按这些已核对字段展示价格，未使用单位不明的总额字段推算售价。

补齐规范化、元数据持久化、旧本地记录按平台消息 ID 补齐及浏览器 CDN 媒体策略。真实商品卡、图片缩略图和放大预览均在运行网页验证；旧会话补齐前后本地消息数量不变。`type=31` 机器人提示和 `type=56` 的 `info.content[].text` 作为系统信息展示，不执行其中的 `click_action`。当前客户端撤回分支使用 `type=1002,info.update_type=3,info.msg_id` 定位被撤回消息，实现已用合成输入验证。

完整后端测试 68 项、前端纯渲染测试 5 项通过。订单、视频与撤回尚无本店真实样本，验证状态详见 README 的消息展示表。本轮未向买家发送消息。
