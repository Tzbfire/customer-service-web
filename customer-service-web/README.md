# 知店 · 商家 AI 客服工作台

多个客服账号共享店铺，使用商家自有模型接口、商品资料和知识库。本文说明当前实现；核对日期为 2026-10-29，功能基线提交为 `d7bc3f1`。协议与实测范围见 [PROTOCOL-AUDIT.md](PROTOCOL-AUDIT.md)。

## 启动与首次设置

要求 uv 和 Python `>=3.12,<3.14`。在本目录运行：

```powershell
uv sync --frozen
uv run --frozen python -m desk
```

访问 `http://127.0.0.1:8765/`。Windows 可双击 `启动.cmd`，使用期间保留服务窗口。首次自行创建管理员，没有预设密码；管理员可在“团队成员”创建客服账号。如果端口已被本工作台占用，直接访问现有页面，不重复启动。

建议按以下顺序设置：

1. “模型配置”填写 Base URL、模型名称和 API Key，保存后测试连接。
2. “店铺连接 → 浏览器登录”，在服务电脑的独立 Chrome / Edge 中完成登录与验证，系统核对店铺后保存登录态。
3. “知识库 → 同步店铺商品并入库”，拉取当前店铺在售商品的文字、规格和 SKU；也可上传自己的商品资料与政策。
4. 图片文字点击“识别详情图”，上传资料和识别结果核对后“确认内容并入库”。
5. “问答测试”核对引用和多轮追问。此入口不向买家发送消息。
6. “店铺连接 → 连接消息”，选择接待方式；新店铺默认为 AI 草稿模式。

登录优先使用已安装的 Chrome / Edge；均不可用时可安装 Playwright Chromium：

```powershell
uv run playwright install chromium
```

浏览器在运行服务的电脑打开，远程客服不会在自己的电脑收到登录窗口。登录过程支持显示窗口、取消、重新打开；超过 10 分钟超时，成功后关闭登录窗口。旧截图遥控输入方案已移除。服务重启后需手动连接消息，接待方式会保留。

## 接待方式与人工协作

| 店铺接待方式 | 新文字咨询处理 | 本地关键词开关 |
| --- | --- | --- |
| 人工接待 | 保存消息，人工处理 | 不调用回答模型 |
| AI 草稿，人工审核发送 | 生成可用草稿，客服接管、核对并发送 | 遵循配置 |
| 有依据时自动回复 | 模型无需人工、引用有效且有资料依据时自动发送，否则保留草稿 | 遵循配置 |
| AI 接管 | 模型直接理解商品资料及上下文，有依据事实回答和不含商品事实的问候/澄清可直接发送 | 始终绕过关键词筛选 |

AI 接管需先配置模型，由管理员自行选择，不会自动为现有店铺启用。不能自动处理的图片、视频及卡片仍需人工查看；退款赔付、投诉、明确要求人工、商品事实无依据或引用异常时进入待处理。模型对回复类型的判断仍需实际业务验证，不能保证回答绝无错误。

会话“接管会话”暂停该会话 AI 接待；“交还 AI”后按店铺当前模式处理后续新消息。切换店铺模式不清除既有人工归属。生成过程中人工接管或切回人工模式会抑制迟到的 AI 回复。这里的接管是本地协作状态，不调用拼多多客服转接接口。

消息按平台 ID 去重。人工发送使用请求标识；相同标识不重复发。超时、中断或无法确认成功时显示“发送结果未确认”，应在商家后台核对，系统不会盲目重发。

## 模型、关键词和多轮上下文

当前适配 Chat Completions 兼容接口；Base URL 可填服务根路径，也可填完整 `/chat/completions` 地址。图片识别要求接口接受 `image_url`（Base64 图片），看图模型留空时使用文字模型。请求明确使用非流式 JSON；支持字符串正文和可见文字内容块，不将推理文本当作识别结果。

“模型配置 → 使用本地关键词检索”：

- 开启（原默认值）：中文分词和 BM25 本地排序，未命中时可直接返回人工提示而不调用模型；商品范围未明确时也可能先要求确认。
- 关闭：完全跳过关键词筛选，将商品范围内已入库资料和前文提交模型理解；无资料也调用模型澄清。资料预算为 60,000 字符，超出时按文档分配部分片段，并向模型注明范围不完整，可能增加输入费用。

上述设置影响普通接待和问答测试；店铺选“AI 接管”时始终使用模型理解流程。测试回答依据区显示模式及是否调用模型。商品 ID 可从本轮或前文买家消息识别，问答测试会延续已明确的商品，避免“详细介绍一下”丢失范围。

未审核资料不参与回答。商品事实和政策限于已入库资料，不同店铺与不同商品不能混用；当前没有向量数据库、训练或微调。关键词关闭不等于放开编造参数、价格或政策。

## 知识来源与审核

| 来源 | 本地保存与入库方式 |
| --- | --- |
| 上传文件 | 提取/识别后为待审核资料，确认后入库 |
| 平台商品结构化资料 | 同步在售列表、详情、SKU，自动建立商品专属知识 |
| 商品详情图 | 保存在线地址供预览；识别后待审核，不因显示图片就已读懂图片 |
| 聊天＋订单总结 | 用户确认运行后分批整理，生成待审核商品知识，不修改客服人设 |

支持 JPG / PNG / WEBP、PDF、DOCX、XLSX、TXT、Markdown 和 CSV。单文件最多 25 MB；PDF 最多 40 页；单图最多 4000 万像素、20 个识别片段；Office 最多 20 张内嵌位图；Excel 最多 15000 行。公式按文本提取，需要核对实际值。文字按 UTF-8 / GB18030 解码，矢量图建议先导出 PDF。

长图按原像素分块；图片、扫描页及 Office 内嵌位图识别使用看图模型。图片任务对临时连接/超时、限流、服务端错误或异常 JSON 最多尝试 3 次，明确标出失败图片位置，已完成详情图复用缓存。鉴权错误、拒绝和输出截断不盲目重试。

### 商品同步

入口：“知识库 → 同步店铺商品并入库”。保存名称、ID、链接、描述、注意事项、分类、平台提供的参数、在售 SKU 组合和同步参考价。详情必须匹配商品 ID 与当前店铺 ID，未提供的信息不推断。

重复同步更新同一份专属资料，不覆盖手工上传资料；人工编辑过的同步知识会保留并提示核对平台快照。完整在售列表未再返回的旧商品，其同步文字和图片知识会停用，不等于平台商品已删除。价格是同步快照，不作实时成交、库存、优惠或履约承诺。

“识别详情图”先说明图片数量、模型调用及费用，确认后执行，结果待审核。单商品最多处理 30 张详情图，下载单图最多 12 MB；超过时需分批上传。相同识别文本不重复建资料；内容变化生成新待审核资料并停用原图片知识。

### 聊天、订单与复购总结

1. 在“店铺连接”完成一次“平台历史＋本地记录”的全部历史导出。
2. 在知识库相应商品点击“聊天＋订单总结”，预览关联案例数量、快照时间和预计模型批次。
3. 确认后读取这些买家的近期及可访问历史订单，再将隐藏编号及常见联系信息的材料提交已配置文字模型。
4. 可暂停、继续，完成的订单查询和模型批次保留进度；模型输出失败可继续重试。部分订单读取失败时生成结果会标为未知。
5. 打开“查看案例与来源”核对原文与订单时间线；“审核总结知识”确认后才进入 AI 可检索资料。

只从明确关联商品卡片的聊天建立商品范围，切换商品后不将后续内容归到原商品。面积必须有买家原话引用，历史答复必须有客服原文与案例/消息引用，伪造引用拒绝写入。过长对话选取片段并注明范围。

按商品和规格保留件数；按不同有效支付订单判断历史多次购买和咨询时间基准后的再次下单。面积原话存在时按其消息时间核对，否则用首次可见商品咨询时间。退款、取消或状态未知不算作有效支付购买；已支付未取消也不代表没有售后。不能从购买件数推算通用耗量或覆盖面积。订单失败不能写成未购买，时间不完整不能断言咨询后无复购。

本功能只生成商品知识。Nuwa 客服 Skill 蒸馏留待用户另行操作，尚未接入或执行；不要求安装 Nuwa 才能运行总结。

## 会话、图片及订单查看

实时接待打开会话时自动只读补取最近 50 条平台记录，与本地消息按平台 ID 合并；支持继续加载更早记录、断线期间中间区间补齐和手动“同步平台记录”。补齐本身不调用 AI、不发送、不接管会话；消息保留原时间排序。没有登录态或读取失败时继续显示本地记录，并明确提示完整性与重试。

“平台历史已加载到底”表示当前接口可获取范围已到最早，不等于平台无限期历史。记录加载状态、当前显示数和本地数量分别呈现。后台检查时间变化不会重建回复输入框。

“历史会话”每页 20 个，可加载更多并筛选已加载买家或内容。历史浏览不导入整批消息、不触发回复，也不推进接收序号；只补充昵称缓存等显示信息。点击“接管并回复”才将该会话最新页导入本地并设为当前客服人工接待。

列表昵称下显示 ID。昵称来自 `user_info.nickname` 或买家资料补查，平台返回的脱敏星号按原样显示，无昵称时保留 ID。新消息不把已知昵称退回数字 ID。

| 消息类型 | 展示方式 |
| --- | --- |
| 文字 / 普通链接 / 引用 | 原文、可点击链接、引用摘要 |
| 图片 | 缩略图、点击放大、Esc 关闭、原图入口与加载失败提示 |
| 商品 / 规格卡 | 平台提供的名称、图片、商品 ID、价格、规格和链接，顶部可显示当前咨询商品 |
| 订单卡 | 关联商品、订单号、规格和平台提供的订单/售后字段 |
| 视频 / 表情 | 原生视频控件及原视频入口；表情描述或图片 |
| 撤回 / 系统 / 常见问题 | 撤回提示、系统文字、问题列表，不执行平台菜单动作 |
| 其他卡片 | 可读摘要和类型提示，不伪造完整卡片 |

媒体只允许支持的平台 HTTPS 域名，包括客户端与买家上传图片使用的精确主机 `chat-img.pddugc.com`。该主机没有扩展为任意 `pddugc.com` 子域。已保存原图链接的旧图片不用重发；更新后刷新页面加载新版脚本。图片、视频和商品卡片“展示”不等于支持从本系统发送这些媒体。

会话标题“查看订单”读取同一买家的近期及更早订单、按订单号去重，展示商品、SKU（如有）、规格、件数、下单时间和支付/订单状态。平台权限和历史期限决定可见范围，失败不视为零订单。

## 店铺删除与对话导出

这两项仅管理员可操作：

- “删除店铺”需输入完整店铺名称；停止连接和登录任务，清除保存的 Cookie 与同步状态，移入“已删除店铺”。知识库、上传原件和聊天保留，可恢复；恢复后重新登录平台。不会删除拼多多店铺或平台消息。
- 有发送、文件解析、商品同步、图片识别、导出或总结任务进行时，删除会被阻止，应先等待完成或暂停支持暂停的任务。
- “导出全部历史对话”默认平台可获取历史＋本地记录，也可选择“仅本地”。显示范围、会话数与消息数；本地导出明确标注不含平台历史，不需要拼多多登录。
- 分页导出支持暂停/继续，失败或重启保留检查点。完成后下载 ZIP 或单独“下载 Markdown”。导出不调用模型、不发消息、不改变接待方式。

ZIP 内容：`messages.csv`（UTF-8 BOM）、`messages.md`（全部会话）、`index.md`、`index.html`、`conversations/*.md` / `*.json` / `*.html`、`manifest.json` 与说明文件。Markdown 保留角色、时间、正文、商品、订单及媒体链接。CSV 防止聊天文字被当成公式执行。

图片和视频只保留在线地址，不打包原媒体。完整导出指当前账号可枚举、可读取的历史与本地记录；运行中新产生的消息不保证进入此次快照。较旧导出可能没有 Markdown，可重新导出。文件和检查点在 `.data/exports/`，需自行管理保留期；删除店铺不会清理它们。

## 团队、部署与备份

管理员配置模型、连接/删除店铺、同步商品、执行总结/导出、维护知识及账号；客服查看资料、测试问题、接管与回复、查看订单。面向同一商家团队，成员共享店铺，不是对外多租户 SaaS。

默认监听本机。已创建管理员的局域网部署可使用：

```powershell
uv run --frozen python -m desk --host 0.0.0.0 --port 8765
```

其他电脑访问服务电脑的局域网地址。远程部署使用 HTTPS 反向代理，并设置 `DESK_SECURE_COOKIE=1`。保持单服务进程（`workers=1`），连接、后台任务和登录浏览器由该进程持有；避免多个程序同时自动接待同一账号。

默认 `.data/` 包含 `desk.sqlite3`、`secret.key`、`uploads/`、`browser/`（登录过程创建的目录）及导出/总结等数据。`DESK_DATA_DIR` 可改路径。Cookie 与 API Key 用 Fernet 加密，密钥保存在同一服务电脑；仅复制数据库而没有密钥不能恢复凭据。建议停止服务后备份整个数据目录；运行中备份 SQLite 需使用 SQLite backup API，不能只复制主数据库而漏掉 WAL。

启动会将中断的解析标失败、未确认发送标不确定，导出/商品/图片/总结任务显示中断或失败，可按相应入口继续或重试。重启不自动重连店铺。

模型调用将所需商品资料、客户问题与上下文发送到你配置的接口，产生 API 用量。图片识别发送图片；聊天订单总结发送经处理的咨询与必要交易信息。自由文本的脱敏不能保证穷尽所有个人信息，执行前需核对材料范围。数据库、密钥、原件、导出、缓存、截图和协议抓取证据不应公开或提交 Git。

忘记工作台密码时，在服务电脑运行：

```powershell
uv run python -m desk.admin 用户名
```

交互设置新密码并撤销旧工作台登录会话。

## 按店铺增量导出聊天记录

进入「店铺连接 → 导出聊天记录」，选择「增量」或「全量」，再选择平台历史＋本地记录或仅本地记录。

- 增量按店铺、数据范围分别保存成功基准，旧版本已经完成的全量导出也可直接作为基准；没有基准时首次增量等同全量。
- 后续文件只包含未导出过的消息及内容更新，包括老会话的新消息、时间较早但延迟发现的消息和撤回更新。更新记录带有变更标记，可按买家、聊天类型和消息 ID 对应以前的记录。
- 基准只有在文件生成完成后才推进；暂停、失败和服务重启均可续传。没有新增时生成空增量文件，不会重复导出之前消息。
- 每次导出生成独立的 ZIP、Markdown 和 CSV 文件，原导出保留；可在店铺卡片查看上次成功时间及本次新增/更新数量。
- 平台增量仍会扫描当前账号可获取的历史，再按消息标识和内容指纹去重；文件更小，但平台读取耗时可能与全量接近，平台已不再返回的记录无法恢复。
- 增量基准保存在 `.data/exports/` 对应成功任务的 `transcripts.sqlite3` 中，请与导出文件一起保留。基准丢失时会提示重新全量导出。

导出只读取记录，不调用 AI、不发送买家消息、不改变接待方式。


## 自定义 AI 系统提示词

在「模型配置 → AI 系统提示词（全局）」填写客服角色、语气和接待流程，点击「保存配置」。最多 30000 字，设置对全部店铺之后生成的 AI 草稿、自动接待和问答测试生效。留空保存即可恢复默认要求，已经生成的草稿不会重写。

商家提示词会与工作台原有的资料依据、人工接管及结构化输出要求一起传给模型。图片转录、商品资料学习和接口连接测试不使用这段客服提示词。若启用本地关键词检索且没有命中，原有流程仍可能直接转人工，不会为执行提示词而额外调用模型。


默认内置 `desk/prompts/pdd_coating_service.md`（来自店主提供的独立 `SYSTEM_PROMPT.md`，原文完整保留），不依赖 `.data/` 或个人技能目录。未设置自定义内容时自动使用，模型配置里可查看、编辑或点击「恢复内置提示词」后保存。自定义内容会覆盖内置版本，留空保存会恢复内置。

生成回复时同时提供当前店铺名称和平台店铺 ID，以区分两家店的产品与政策。内置知识为带适用条件的历史参考，涉及待核实项仍需人工确认；资料引用和结构化输出继续按工作台现有协议执行。
